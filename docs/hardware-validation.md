# 实机验证记录

日期：2026-10-22。环境：Ubuntu 22.04.5 LTS，AirPods Pro 3。
这份记录不包含设备蓝牙地址、用户配置文件或原始备份。

## 授权与连接

1. 耳机已配对并连接，BR/EDR ATT PSM `0x001f` 可连接。
2. 未配置 Apple DeviceID 时，读取通透句柄 `0x0018` 返回 `01 0a 18 00 0e`。
3. 用户运行仓库配置工具，设置 `DeviceID = bluetooth:004C:0000:0000`，重启蓝牙并重新连接耳机。
4. 再次读取成功，参数布局为 104 字节。

## 读取与写入

初始值：自定义通透关闭；左右耳增音、音调、环境噪声降低均为 0；对话增强关闭；
自己声音增音为 0.5。

执行修改：`enabled=true`，左右耳 `amplification=-0.2`。
工具在写入前保存完整原始值，收到 ATT Write Response 后读回，完整参数字节与请求一致。
随后关闭 ATT 连接，在另一次独立连接上重新读取，仍得到相同值。
实际浮点读数为 `-0.20000000298023224`，是 −0.2 的 float32 表示。

音调、环境噪声降低、对话增强和自己声音增音没有修改。

## BlueZ 接管 ATT 后的连接拒绝修复

随后 BlueZ 完成 GATT 服务发现，直接连接 PSM `0x001f` 返回 `ECONNREFUSED`，
而耳机仍处于音频连接状态。通过 BlueZ `ReadValue` 可以读取相同的 104 字节数据。

修复后自动按设备和 UUID 选择 BlueZ GATT 传输。实机 `doctor --json` 报告
`ok=true`、`backend=bluez`，返回当前参数。另进行了同值写入测试：先备份原值，
再经 BlueZ `WriteValue`（此特征只声明无响应写入）写回完全相同的值，随后
`ReadValue` 验证完整字节一致。没有改变任何调节参数，也没有重启蓝牙或断开音频。

## 0.2 控制中心

2026-10-22：在同一副 Pro 3 上连接 AACP PSM `0x1001`，完成握手、功能协商和通知订阅。
收到左右耳电量、型号、固件、佩戴状态和通透模式通知。充电盒状态为 disconnected，
因此电量正确显示为未知，没有将其 0 值当作真实电量。

在用户级后台服务上执行通透 → 降噪 → 通透，每次切换都收到对应模式的设备确认。
保存当前声音设置及模式为本地预设，并成功重新应用。此预设中的声音参数与耳机原值一致，
因此没有额外写入声音参数；原先实机通透写入验证见上文。

尚未实机切换到自适应或关闭模式；这两项提供接口，但只在设备确认后才报告成功。
型号信息、实时电量和模式通过同一服务提供给 GUI 与 JSON CLI。
